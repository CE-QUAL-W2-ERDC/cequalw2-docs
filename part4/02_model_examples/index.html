    Model Examples Distributed with the Model Release¶

    The example problems released with the code are listed below. Each example is described in detail in this chapter.

    • Columbia Slough Estuary (Excel control file)
    • DeGray Reservoir (Excel control file) with sediment diagenesis and vertical algae migration
    • Detroit Reservoir
    • Long Lake (Excel control file)
    • Multiple Water Body Cascade
    • Particle Tracking
    • Sediment Diagenesis Example
    • Spokane River (both old input format and CSV input format)
    • SysTDG Columbia River (Bonneville Reservoir)

    Two additional sets of examples are also released with the model download: one for the United States Geological Survey (USGS) Auto Port Selection feature and one for using W2Post for plotting calibration profiles. The USGS Auto Port Selection examples are in the directory USGS Examples for using USGS Auto Port Selection Algorithm and include examples described in the README.txt file provided by Stewart Rounds of the USGS.

    The W2Post example is included in the download directory W2tools post-processor integrated with W2control preprocessor. This includes the DeGray Reservoir example with computed temperature calibration data and statistics.

    Columbia Slough Estuary¶

    Waterbody Description¶

    The Upper and Lower Columbia Slough are each long (about 9 miles) and narrow (50--200 ft wide) water bodies in the Portland metropolitan area in Multnomah County, Oregon. The Lower Columbia Slough is connected to the Willamette River near its mouth with the Columbia River, where it experiences a tidal fluctuation of its water surface between 1 and 3 ft.

    Inflows to the Lower Columbia Slough include:

    • Combined sewer overflows (CSOs)
    • Stormwater from stormwater pipes and pump stations on the northern side of the Lower Slough
    • Water from Smith and Bybee Lakes
    • Leachate from St. John's Landfill
    • Pumped and gravity inflows from the Upper Columbia Slough at Multnomah County Drainage District #1 (MCDD1)

    The example problem is set up as a 2-branch model of the Lower Columbia Slough.

    The Upper Columbia Slough, termed the "Middle" and "Upper" Slough, was historically maintained to provide irrigation water to agricultural and commercial users in the summer months. The Upper Slough is connected by pipes and an overflow weir during the fall, winter, and spring to Fairview Lake. During the summer, Fairview Lake is connected to the Upper Slough only by flow over and leakage through the weir.

    Water is also pumped from the Upper Slough to the Lower Columbia Slough at a pump station at MCDD1 and from the Upper Slough to the Columbia River at MCDD4 (Multnomah County Drainage District #4). At MCDD1, pipes also allow gravity flow from the Upper Slough to the Lower Slough. Other inflows to the Upper Columbia Slough include groundwater and stormwater from the Portland International Airport and other industrial, commercial, and residential neighborhoods in the area.

    The model has 2 branches comprising the main arm of the Lower Slough and the branch named North Slough. The vertical grid spacing is 0.305--0.61 m (1--2 ft). Details of the bathymetry are shown in Table 1.

    Key Features¶

    This example demonstrates how to use an external head boundary condition and set up files for that boundary. This is an older example using the old input format for head boundary conditions. The User Manual Part 3 shows how these files can be developed in a simpler format, especially if there is no stratification in the Willamette River at the external head boundary condition location.

    The model uses the file tdh_br1.npt for the temperature downstream head external boundary condition. An updated, simpler format file is also included in this example, tdh_br1.csv. A similar CSV file could be developed for the cdh_br1.npt file following guidelines in the User Manual Part 3. The control file for this example is generated from the Excel file w2_con_ColSlough.xlsm, which produces the file w2_con.csv.

    DeGray Reservoir with Sediment Diagenesis and Vertical Algae Migration¶

    Waterbody Description¶

    DeGray Reservoir is located on the Caddo River in south-central Arkansas and is the site of the first water quality test application of CE-QUAL-W2. Impounded in 1969, the reservoir is used for power generation, flood control, and recreation. DeGray is classified as a monomictic, deep storage reservoir.

    This example demonstrates several features of the CE-QUAL-W2 model, including:

    • Sediment diagenesis
    • Vertical migration of algae
    • Contour plotting for temperature
    • Environmental performance
    • Fish habitat

    Table 3. DeGray Reservoir physical characteristics.

    Area Volume Average depth Maximum depth Residence time
    5,092 ha 613,692 acre-ft 14.9 m 56 m 560 days

    Model Grid¶

    DeGray Reservoir was originally modeled as a one-branch system with no tributary inflows. The grid has one orientation angle for the entire grid. Under typical modeling situations, the orientation angle would vary by segment, and the grid should include several model side branches rather than just one.

    The model vertical grid spacing is 2 m, which is coarse relative to the typical 1 m or finer grid spacing. The outlet location is in layer 13.

    Table 4. Branch and segment layout for DeGray Lake.

    Branch Branch length Segment lengths Maximum width Layer height Upstream segment Downstream segment
    1 30 km 1000 m 5530 m 2 m 2 31

    Key Features¶

    This example demonstrates how to set up and use the fish habitat feature (output file habitat.csv) and the environmental performance features. Output files include envrprf_t_1.csv for temperature and envrprf_c_1.csv for concentration of state variables, used to evaluate a model simulation. These are configured using the input files w2_habitat.npt and w2_envirprf.npt. Descriptions of these files are provided in the User Manual Part 3.

    Output files are also written for the W2Post post-processor and for contour plotting of depth vs. time and temperature (input file w2_lake_river_contour.csv).

    The control file for this example is generated from the Excel file w2_con_DeGray.xlsm, which produces the file w2_con.csv.

    This example also has sediment diagenesis enabled (input file w2_diagenesis.npt) and vertical migration of algae enabled (input file w2_AlgaeMigration.csv). See the User Manual Part 3 for details on these features. All auxiliary input files are tabs in the Excel file w2_con_DeGray.xlsm.

    Detroit Lake¶

    Waterbody Description¶

    This example explores model execution, fish habitat analysis, and travel time of particles released at the upper end of the reservoir. The model represents Detroit Reservoir in Oregon, USA. The original model was developed by the USGS (Sullivan et al., 2007) and has been simplified for this example.

    Model Grid¶

    The model has 4 branches and 31 segments. The vertical layer height is approximately 2 m. The model files are organized in a zipped file with input files in a subdirectory called InputFiles. All output files are written to the directory where the model executables are located, although output can be directed to a separate directory using guidelines in the User Manual.

    Model Predictions¶

    After running the preprocessor and model executable, two aspects of the model predictions are highlighted:

    1. Flow balance summary
    2. Fish habitat volume

    Flow Balance Summary¶

    The output file for overall flow balance is flowbal.csv. This file reports the flow in and out as well as evaporation losses over the 2002 simulation year. The file contains model-predicted evaporation losses, mass balance errors (very small), and inflow and outflow volumes.

    Fish Habitat Volume¶

    The output file for fish habitat volumes is habitat.csv. This file reports habitat volumes and percent volumes for each species listed at the beginning of the file. The file opens in Excel, and the model-predicted fish habitat for striped bass can be viewed as a percentage of the reservoir volume over the year (Figure 12). This reservoir is too cold in the winter months for this species.

    Additional model features to explore include suspended solids distributions in the reservoir and stratification dynamics. The W2Post graphical user interface (GUI) post-processor provides contour plots of temperature stratification, time series plots, and profile plots.

    Multiple Water Body Cascade¶

    Overview¶

    This example focuses on using 3 waterbodies of a river system that cascade from one to the other in linear fashion with the multiple processor approach. This approach is discussed in Part 3 of the User Manual. The purpose of this example is to show how to reduce computational time for running multiple waterbodies.

    The user has several choices for running this system of 3 waterbodies:

    • Run all 3 waterbodies as one model. This approach is simpler to manage since all files are in one directory, but the model takes the longest time to run since all waterbodies are limited to the shortest numerical time step in the 3-waterbody domain.
    • Run waterbodies sequentially. Run the upper waterbody (WB1) first, then copy the outflow from WB1 to the next waterbody (WB2) and run WB2. Repeat for the last waterbody (WB3). This approach is well-suited to using a batch file to transfer files automatically and setting CLOSEC to ON to close the dialog box automatically. Each waterbody will run at its maximum time step independent of the other waterbodies and hence will be faster than the first choice.
    • Use the multiple waterbody model. The code manages the transfer of information from one waterbody to the other and runs the models simultaneously based on upstream data availability. Instead of waiting for the upstream run to complete, the downstream model starts running when information is available from upstream. With multiple cores, the waterbodies run on separate computer cores and the run finishes close to the time of the limiting waterbody.

    Waterbody Description¶

    The example is from a multiple waterbody model of the Chehalis River in Washington, USA. The Chehalis River Basin is located in southwest Washington State (see Figure 25). The drainage area to the Chehalis River is over 2,000 square miles, with area existing within five counties: Lewis, Thurston, Grays Harbor, Pacific, and Cowlitz (WADOE, 2001).

    The Chehalis River originates in Coast Range east of Willapa Bay, and also drains the western foothills of the Cascades and the southern Olympic Mountains. It ultimately flows into Grays Harbor and the Pacific Ocean, totaling over 125 miles in length.

    Model Grid¶

    The Chehalis River was modeled from upstream of Pe Ell (RM 108) to Porter, WA (RM 33.3). Only the mainstem Chehalis River was modeled and was discretized into 10 model branches and 9 waterbodies. The physical characteristics of the river varied widely, and multiple branches allowed for separate characteristics (such as branch slope) unique to each branch to be implemented in the model. The upstream reaches had steep gradients with riffles and pools. It is the first 3 waterbodies or first 3 branches that were used in this example (see Figure 26). Table 8 shows the characteristics of each waterbody.

    Table 8. Summary of waterbody and branch segments and layers for the 3 waterbodies in this example.

    Waterbody Branch Starting active segment Ending active segment Number of segments Branch length (m) Number of layers Vertical layer thickness (m) SLOPE
    1 1 2 6 5 2000 20 1 0.01600
    2 2 2 21 20 8000 20 1 0.00200
    3 3 2 30 29 11600 20 1 0.00200

    Running the Example¶

    For this example, follow the steps outlined in User Manual Part 3 for using this model feature. The model user starts running the first waterbody, then starts running the second waterbody, then once output has started in the second waterbody, the model user starts the third waterbody. The model waits until enough output has been generated by the upstream model before starting on the downstream models.

    Each model waterbody runs on a different model processor. Overall this approach has saved considerable computational time compared to running the model all under one model environment.

The User Manual Part 3 describes in detail the input file format and the model output files that describe the particle paths and histogram of the time history of the particles in terms of temperature, velocity, and depth the particles experienced over time.

    This code also shows how to use the feature where the longitudinal eddy viscosity and diffusivity scale with the predicted longitudinal velocity, which affects the random movement of particles in the x-direction.

    SysTDG Columbia River - Bonneville Reservoir¶

    Overview¶

    This is an application on the Columbia River using the SYSTDG model for estimating the discharge total dissolved gas (TDG) at Bonneville Dam. The model consists of 1 waterbody, 1 branch, and 77 model segments as shown in Figure 36. The main branch 1 of the Columbia River side view is shown in Figure 37.

    Key Features¶

    This example illustrates how to turn on TDG and use the state variables N₂ gas and O₂ gas to predict TDG gas concentrations in the pool area and at the dam as a result of spillway operation. The special input file, w2_systdg.npt, is described in User Manual Part 3.

    The SysTDG algorithm only operates on gates. Hence, gates were used for the spillways and powerhouse withdrawals since specified flows can be prescribed for a gate just as a withdrawal or structure.
