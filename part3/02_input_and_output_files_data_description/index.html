    Input and Output Files Data Description¶

    This chapter describes all input and output files used by CE-QUAL-W2 Version 4.5. The model requires a control file and various ancillary input files for bathymetry, meteorology, boundary conditions, and initial conditions. It produces output files for snapshots, time series, profiles, contour plots, kinetic fluxes, mass/flow balances, and diagnostic information.

    All input files support two formats unless otherwise noted:

    • Fixed format (space delimited): Fields are F8.0 format (8 characters wide) with right-justified variable names on line 3. The first two lines are comments.
    • Free format (comma delimited): Indicated by a $ character as the first character on line 1. Fields are comma separated with no width restriction. The first three lines are comments/headers.

    Free Format Recommendation

    The free-format (comma-separated values, CSV) option is recommended for new applications. It removes the 8-character field width restriction and simplifies data preparation using spreadsheet software.

    Input Files¶

    Control File¶

    The control file is the primary input file for CE-QUAL-W2. It defines the computational grid, simulation time, boundary conditions, hydraulic and kinetic parameters, constituent controls, and output specifications. Two formats are supported:

    • w2_con.npt: Fixed-format text file with 8-character fields
    • w2_con.csv: Excel/CSV format with the same information organized in worksheet tabs

    CSV Control File

    When using w2_con.csv, the graph.npt file is not needed because many of its variables are included directly in the CSV control file format.

    The control file is organized into a series of "cards," each controlling a specific aspect of the simulation. The following sections describe each card and its parameters.

    MISCELL¶

    The [MISCELL] card defines miscellaneous control parameters that enable or disable several optional features of the model. Many of these features were first implemented in Version 3.7.

    Field Variable Value Description
    1 (Ignored by code)
    2 NDAY Integer Maximum number of output dates or timestep-related changes
    3 SELECTC Character Turn ON/OFF/USGS automatic port selection from a multiple outlet structure where level is chosen by the model to reach a temperature target
    4 HABTATC Character Turn ON/OFF habitat analyses for fish and eutrophication variables
    5 ENVIRPC Character Turn ON/OFF environmental performance criteria
    6 AERATEC Character Turn ON/OFF aeration to waterbody with dissolved oxygen probe control
    7 INITUWL Character Turn ON/OFF initial water surface slope and velocity calculation for a river system
    8 ORGCC Character Turn ON/OFF use of C for organic matter basis
    9 SED_DIAG Character Turn ON/OFF sediment diagenesis processes
    10 DZMAX Real Value of DZ when there is a density instability (m² s⁻¹)

    NDAY is the maximum number of output dates that will be used in the simulation. This should be set to a value greater than or equal to the maximum of timestep, snapshot, screen, profile, vector, contour, time series, withdrawal, and restart number of dates that are used to define when output frequencies change, or, in the case of the timestep-related cards, when the maximum timestep or the fraction of the timestep change. A default of 100 is appropriate for most simulations.

    SELECTC turns ON or OFF the automatic port selection for a multiple outlet withdrawal structure at a downstream end of a branch. When set to ON, the model reads the control file w2_selective.npt. Setting SELECTC to USGS allows the model to decide which outlet to use to meet temperature targets. When set to OFF, the algorithm is not used.

    HABTATC turns ON or OFF the fish habitat analysis and other useful analyses for eutrophication studies. When ON, the model reads the control file w2_habitat.npt.

    ENVIRPC turns ON or OFF the environmental performance analysis for user-chosen model state variables, including temporal and volume-weighted averages and histograms. When ON, the model reads the control file w2_envirpc.npt.

    AERATEC turns ON or OFF aeration at specified segments and layers. When ON, the model reads the control file w2_aerate.npt.

    INITUWL turns ON or OFF a computation of the initial water level and velocity for any branch with a non-zero slope. A computation of the normal depth profile is used instead of the water surface profile given in the bathymetry file. When ON, the model writes the output file init_wl_u_check.dat showing the initial water surface elevations, normal depths, and velocities. This allows smoother running of river models at the beginning of the simulation.

    ORGCC turns ON or OFF the use of C as a basis for organic matter compartments. When ON, the model uses LPOC, RPOC, LDOC, RDOC (L is labile, R is refractory, OC is organic carbon, D is dissolved, P is particulate) rather than LPOM, RPOM, LDOM, RDOM (where M is matter on a dry weight basis).

    SED_DIAG turns ON or OFF reading of the sediment diagenesis input file. When sediment diagenesis processes are turned ON within the input file w2_diagenesis.npt, both zero-order and first-order SOD are automatically turned OFF within the model.

    DZMAX is the maximum value of vertical diffusion when there is a density instability or inversion. If the value is positive, it is used directly as DZ during a density inversion. If the value is negative, it is a multiplier of the computed DZ from the chosen turbulence closure model (such as TKE) to increase mixing during a density inversion. For example, if DZMAX = -100, the DZ during an inversion would be the TKE-computed value multiplied by 100. A value of 1000 m² s⁻¹ was hard-wired in legacy W2 models.

    DZMAX Setting

    A value of 1000 m² s⁻¹ can cause excessive mixing over multiple vertical layers. Consider using a negative value (multiplier) to scale the computed turbulent diffusivity, or set DZMAX to a smaller positive value if water quality instabilities occur during inversions.

    MISCELL     NDAY SELECTC HABTATC ENVIRPC AERATEC INITUWL   ORGCC SEDIAG   DZMAX
             100    USGS      ON      ON      ON     OFF     OFF    OFF   1000.

    PIPES¶

    The [PIPES] card specifies the characteristics for each pipe included in the simulation. This card is required when NPI > 0 on the [IN/OUTFLOW] card.

    Field Variable Type Default Description
    1 (Ignored by code)
    2 IUPI Integer Pipe upstream segment number
    3 IDPI Integer Pipe downstream segment number
    4 EUPI Real Upstream invert elevation, m
    5 EDPI Real Downstream invert elevation, m
    6 WPI Real Pipe diameter, m
    7 DLXPI Real Pipe length, m
    8 FPI Real Bottom roughness (Manning's friction factor)
    9 FMINPI Real Minor friction losses
    10 LATPIC Character Downstream or lateral pipe withdrawal: DOWN or LAT
    11 DYNPIPE Character Dynamic pipe switch: ON or OFF

    [IUPI] and [IDPI] specify the upstream and downstream segment locations of the pipe, respectively. [EUPI] and [EDPI] set the upstream and downstream invert elevations. [WPI] specifies the pipe diameter and [DLXPI] specifies the pipe length. [FPI] sets the bottom roughness value (Manning's friction factor) and [FMINPI] specifies the minor friction losses.

    Setting [LATPIC] to DOWN specifies that the pipe is at the downstream end of the segment. In this case the water surface elevations are computed based on the right-hand side water surface elevation of the segment. The elevation of the right-hand side of the segment is estimated using the water surface slope of segment IUPI and IUPI-1. Momentum from the outflow is preserved as in a downstream structure withdrawal. If [LATPIC] is set to LAT, the outflow is treated as a lateral withdrawal at the segment center elevation. In both cases selective withdrawal is used in the computations.

    For a downstream segment that is at the upstream end of a branch, the inflow is treated as an inflow. If it is input to a downstream segment that is not the upstream end, it is treated as a tributary inflow.

    When [DYNPIPE] is ON, the model reads a file called dynpipe.npt. This file uses the same format as a time series file with a time series of Julian day and a number usually from 0 to 1. The number is multiplied by the flow rate computed for the pipe, allowing the user to turn the pipe on or off or reduce flow for given periods of time. This input is treated as a step function (no linear interpolation between successive values).

    PIPE       IUPI   IDPI   EUPI   EDPI    WPI  DLXPI    FPI FMINPI LATPIC DYNPIPE
Pi 1         24     28   28.0   27.0    0.5  230.0  0.065   0.10   DOWN      ON

    PIPE UP¶

    The [PIPE UP] card specifies how inflows and outflows for the upstream pipe location are handled. This card is required when NPI > 0.

    Field Variable Type Default Description
    1 (Ignored by code)
    2 PUPIC Character DISTR Inflow placement at upstream pipe segment: DISTR, DENSITY, or SPECIFY
    3 ETUPI Real Top elevation for pipe inflows when using SPECIFY option, m
    4 EBUPI Real Bottom elevation for pipe inflows when using SPECIFY option, m
    5 KTUPI Integer Top layer above which selective withdrawal will not occur
    6 KBUPI Integer Bottom layer below which selective withdrawal will not occur

    Setting [PUPIC] to DISTR distributes the inflows evenly from the water surface to the bottom active layer. Setting it to DENSITY places the inflows into a layer with similar density. Setting it to SPECIFY allows the user to specify a top and bottom elevation into which inflows enter. If the SPECIFY option is used, [ETUPI] and [EBUPI] are used to specify the top and bottom elevations over which the inflows are distributed.

    [KTUPI] and [KBUPI] set the upper and lower layers above and below which outflow does not occur in the selective withdrawal algorithm.

    PIPE UP    PUPIC  ETUPI  EBUPI  KTUPI  KBUPI
Pi 1       DISTR                    2     19

    SPILLWAYS¶

    The [SPILLWAYS] card specifies the spillway (or weir) characteristics for each spillway in the simulation. This card is required when NSP > 0 on the [IN/OUTFLOW] card.

    Field Variable Type Description
    1 (Ignored by code)
    2 IUSP Integer Spillway segment location
    3 IDSP Integer Downstream segment where spillway outflow enters
    4 ESP Real Spillway elevation (crest), m
    5 A1SP Real α₁, empirical coefficient for free-flowing conditions
    6 B1SP Real β₁, empirical coefficient for free-flowing conditions
    7 A2SP Real α₂, empirical coefficient for submerged conditions
    8 B2SP Real β₂, empirical coefficient for submerged conditions
    9 LATSPC Character Downstream or lateral withdrawal: DOWN or LAT

    [IUSP] and [IDSP] specify the upstream and downstream segments for the spillway. Setting [IDSP] to 0 allows the user to spill water and have that water lost from the system.

    The model requires the user to specify a head (h, m) versus flow (Q, m³ s⁻¹) relationship in the following form for freely flowing conditions:

    Q = α₁ Δh^β₁

    where α₁ is an empirical parameter, β₁ is an empirical parameter, Δh = Z_u - Z_sp, Z_u is the upstream head (m), and Z_sp is the spillway crest elevation (m).

    For submerged conditions:

    Q = α₂ Δh^β₂

    where α₂ is an empirical parameter, β₂ is an empirical parameter, Δh = Z_u - Z_d, Z_u is the upstream head (m), and Z_d is the downstream head (m).

    Submerged conditions are defined when the tailwater depth over the upstream energy head (static head and velocity head) is greater than 0.67. Even though negative flow rates are possible using the second equation when the downstream head is greater than the upstream head, these results should be used with caution since rarely are rating curves done for reverse flow. The user should ensure a smooth transition between submerged and free-flowing conditions by proper choice of model coefficients.

    Coefficient Scaling

    The A2SP coefficients may be about 5 times larger than the A1SP coefficients if the B1SP and B2SP coefficients are unchanged. See Part 2 for further information.

    Setting [LATSPC] to DOWN specifies that the spillway is at the downstream end of the segment. In this case the water surface elevations are computed based on the right-hand side of segment IUSP. If [LATSPC] is set to LAT, the outflow is treated as a lateral withdrawal at the segment center elevation. In both cases selective withdrawal is used in the computations.

    SPILL GAS¶

    The [SPILL GAS] card turns on or off spillway gas computations and specifies the parameters that define the dissolved gas relationship. This card is required when NSP > 0.

    Field Variable Type Default Description
    1 (Ignored by code)
    2 GASSPC Character OFF Dissolved gas computations: ON or OFF
    3 EQSP Integer Equation number for computing dissolved gas (1--4)
    4 ASP Real a coefficient in dissolved gas equation
    5 BSP Real b coefficient in dissolved gas equation
    6 CSP Real c coefficient in dissolved gas equation

    If dissolved gas computations are turned ON via [GASSPC], an equation number must be supplied (1 to 3). Based on the equation number, two or three coefficients are required. If [IDSP] is 0, the model will not compute any effects of gas transfer even if [GASSPC] is ON, since the water exiting the spillway or weir is not accounted for in the system. This algorithm computes gas effects for flow from upstream to downstream and there is no adjustment of dissolved oxygen for reverse flow.

    The gas production equations are empirical correlations between total dissolved gas (TDG), usually measured a mile downstream of the dam after turbulence from the spillway has subsided, and discharge, usually measured in kcfs.

    Equation # (EQSP) Equation Description
    1 %TDG = a q_s + b Linear function of spill on a per-spillway basis. q_s = individual spillway spill (kcfs). C_O₂ = %TDG x C_sO₂.
    2 %TDG = a + b e^(c q_s) Bounded exponential of spill on a per-spillway basis. C_O₂ = %TDG x C_sO₂.
    3 D_a/D_b = 1 + 0.38ab(1 - 0.11c) / (1 + 0.046T)c Reaeration effect for small height weir or dam (< 10 m). c = water fall height (m). C_O₂ = C_sO₂ - D_b.
    4 C_O₂ = FRAC x C_into turbine O₂ Reaeration increased by a fraction of incoming dissolved oxygen. b = 0 or 1 (time series file w2_spX_DO.csv); c = 0 or 1 (saturation limit).

    TDG Limits

    For equations 1 and 2, the maximum TDG allowed is 145%. If TDG is computed to be less than 100%, there is no effect of the spillway or gate on reaeration.

    PUMPS 1¶

    The [PUMPS 1] card specifies the characteristics of the pumps in the system. This card is required when NPU > 0 on the [IN/OUTFLOW] card.

    Field Variable Type Default Description
    1 (Ignored by code)
    2 IUPU Integer Upstream segment number where water is withdrawn
    3 IDPU Integer Downstream segment number where water enters (or negative)
    4 EPU Real Elevation of pump, m

    6 ENDPU Real Ending day of pumping, Julian day

    8 EOFFPU Real Pump stopping elevation, m
    9 QPU Real Pump flow rate, m³ s⁻¹

    Pumps can also be thought of as "water level control" since the model user can add a water level rule curve and have the model decide how much outflow is necessary to keep the water level within limits.

    Setting [LATPUC] to DOWN specifies that the pump is at the downstream end of the segment. If [LATPUC] is set to LAT, the outflow is treated as a lateral withdrawal at the segment center elevation. In both cases selective withdrawal is used.

    When [DYNPUMP] is ON, an input file (dynpumpX.npt where X is the pump number) is read containing JDAY, EPU, EONPU, and EOFFPU as a time series. Values are treated as step functions (no interpolation).

    Pump Flow Direction

    For the pumps algorithm, in contrast to gates, spillways (weirs), and pipes, flow is only in one direction (from the upstream segment only).

    CST COMP¶

    The [CST COMP] card (Constituent Computations) controls whether water quality constituent computations are performed.

    Field Variable Type Default Description
    1 (Ignored by code)
    2 CCC Character OFF Constituent computations, ON or OFF
    3 LIMC Character OFF Output algal growth limiting factor, ON or OFF
    4 CUF Real 2 Constituent kinetics update frequency. If > 0, number of transport iterations between kinetics updates. If < 0, the time in Julian days between kinetics updates.
    5 CO2PPM Real 415. Atmospheric CO₂ concentration in ppm. Default depends on year of simulation.
    6 CO2YRLY Character ON Use built-in regression for global average CO₂ in ppm (NOAA 1920-2019), ON or OFF

    CCC determines whether constituent computations are performed. If set to OFF, all constituent control cards are ignored. Individual constituent computations are controlled on the CST ACTIVE card. During initial calibration runs for freshwater systems, constituent computations are usually turned off until temperature, water surface elevations, and velocities are calibrated.

    LIMC specifies whether the factor limiting algal growth is output to the snapshot file and to the time series file. The limiting factor (between 0 and 1) for N, P, and light is written to these files.

    CUF specifies how many transport iterations are performed before constituent kinetics are updated. This option reduces computation time. Set CUF to 1 during initial calibration. If CUF is negative, it specifies the update interval in Julian days (e.g., CUF = -0.01 updates kinetics every 0.01 days).

    CO2PPM is the atmospheric CO₂ concentration used to compute the partial pressure of CO₂ gas. This value is ignored if CO2YRLY is ON. These two variables only affect the computation of total inorganic carbon (TIC) and pH calculations.

    Calibration Strategy

    During initial calibration, set CCC to OFF and calibrate temperature and water surface elevations first. Then turn on constituents with CUF = 1 for initial water quality calibration.

    Example

    CST COMP     CCC    LIMC     CUF  CO2PPM CO2YRLY
              ON     OFF      10    415.      ON

    Bathymetry File¶

    The bathymetry file contains information specifying the segment lengths, water surface elevations, segment orientations, bottom friction, layer heights, and average widths for each grid cell. A separate bathymetry file is required for each waterbody.

    The following guidelines apply to file preparation:

    1. Number the branches starting with the mainstem as branch 1. Number remaining branches consecutively, starting with the most upstream branch and proceeding downstream.
    2. Each branch must be surrounded by a segment of boundary cells (cells with zero widths) on both the upstream and downstream ends. This requirement results in two segments of zero widths between each branch.
    3. Boundary cells must also be included at the top and bottom of each segment.
    4. Cell widths start at layer 1 and continue to the maximum number of layers [KMX]. The number of layers specified in this file must match the value of [KMX] in the control file.
    5. Only cells that are potentially active have non-zero widths. The first layer, boundary segment cells, and cells below the reservoir bottom elevation at a given segment have zero widths.
    6. A separate bathymetry file is required for each waterbody.
    7. The segment angles are relative to North. Segments oriented from East to West would have an angle of π/2.

    Two formats are supported: fixed format and CSV format.

    Fixed Format¶

    For the fixed-format bathymetry file, the following additional guidelines must be followed:

    1. The first three lines are ignored and can be used to comment the input file.
    2. Segment lengths, water surface elevations, segment orientations, layer heights, and cell widths at each segment are preceded by two lines that are ignored. These can be used to comment each individual segment's bathymetry.
    3. Input format for each cell width is F8.0 with 10 cell widths per line.
    4. If there are more cell widths than can fit on one line, they are continued immediately on the next line.

    CSV Format¶

    Since Version 3.7, the bathymetry can be input as a comma-delimited file (CSV format). This allows the file to be assembled in a spreadsheet such as Excel. To use the CSV format, the model user must insert the $ character as the first character of the first line.

    Line 1: Include the $ character as the first character. The rest of this line is ignored and can be used for comments.

    $1981 Bluestone Reservoir Bathymetry

    Line 2: Title SEG:I, followed by a header for each model segment. This line is ignored by the model.

    SEG: I 1 2 3 4 5 6 7

    Line 3: Title DLX, followed by DLX in m for each segment.

    DLX 1046.4 1046.4 1046.4 965.9 965.9 764.7 764.7

    ELWS 430.1 430.1 430.1 430.1 430.1 430.1 430.1

    Fish Habitat Volumes¶

    Fish Criteria Section¶

    The first line after the title is ignored by the model. The second line specifies:

    Field Description
    Number of fish species Integer specifying how many species to expect (up to 9)
    Output filename Output filename in quotations (e.g., 'habitat.csv')
    DOVOL ON or OFF: compute volume less than 1 mg/L dissolved oxygen

    For each fish species, specify the name, a low and high temperature limit in °C, and a dissolved oxygen target in mg/L. If the model user is not modeling dissolved oxygen, the DO limits are ignored. The habitat volume uses the following criteria for acceptable habitat:

    • Model temperature > TEMP-low and <= TEMP-high
    • Dissolved oxygen >= DO limit

    Volume-Weighted Averages Section¶

    The number of segments and output filename are specified on one line. The segment numbers for volume-weighted averages are listed on the next line, separated by commas. The model outputs volume-weighted eutrophication variables (dissolved oxygen, nutrients, and chlorophyll a) at these segments. The code caps dissolved oxygen greater than saturation to 100% saturation for computing averages.

    Surface-Weighted Averages Section¶

    The number of active surface layers to average and the output filename are specified. In many cases a value of 1 gives a surface average; a value of 4 averages the top 4 active layers for an epilimnetic average. The model also outputs the layer-average light extinction coefficient for comparison with field data.

    Sediment Accumulation Output¶

    The sodsed.opt output file prints the first-order sediment organic matter accumulation at each segment as a function of time. It sums all the sediment accumulated at all vertical layers. The output is in grams of organic matter. This allows the model user to evaluate how changes in organic loading to the sediments affect the rate of accumulation and spatial distribution.

    CDR Distance from the centerline of the river segment to the shade controlling line of vegetation on the right bank (m).
    SRFL1 Shade reduction factor, left bank (0 to 1). Applies from JDSRF1 to JDSRF2 (and over multiple years). Based on extent of vegetation along the segment length and density.
    SRFL2 Shade reduction factor, left bank (0 to 1). Applies from JDSRF2 to JDSRF1.
    SRFR1 Shade reduction factor, right bank (0 to 1). Applies from JDSRF1 to JDSRF2.
    SRFR2 Shade reduction factor, right bank (0 to 1). Applies from JDSRF2 to JDSRF1.
    TOPO1 to TOPO18 Topographic inclination angle (radians) for every 20° around a segment starting with TOPO1 at 0° North and moving clockwise.
    JDSRF1 Julian day for which SRF #1 starts to apply (leaf-out conditions for deciduous trees).
    JDSRF2 Julian day for which SRF #2 starts to apply (when deciduous trees lose their leaves).

    Vegetation Elevation¶

    The algorithm uses elevations for the grid development, so the vegetation's elevation is used instead of height. If shading is due to brush along a river, the top elevation of the brush would be used in the model. The tree top elevation consists of the vegetation height and the bank surface elevation where the vegetation is standing. Tree top elevations should be collected for both river banks.

    Centerline Distance¶

    The centerline distance is the distance between the river centerline and the controlling vegetation on each bank. The information will vary for each bank depending on the location of the river centerline and the offset of the vegetation from the wetted edge. The frequency of the distances should match the tree top elevation data and reflect the variability of the vegetation.

    Shade Reduction Factor¶

    The shade reduction factor is based on the density and extent of the vegetation along the length of each model segment. If shade-producing vegetation exists along only half the length of a segment and was 100% opaque, a shade reduction factor of 0.50 would be used. If shade was due to vegetation along only half of the segment with 80% density, then a shade reduction factor of 0.40 would be used. The shade reduction factors, SRFR1 and SRFR2, are expressed as a fraction from 0.0 to 1.0. The shade reduction factor should be developed for both banks and can be used as a calibration parameter if field data are uncertain or incomplete.

    Topographic Shading¶

    In addition to the vegetation near a river, the local topography can influence the amount of solar radiation reaching the water surface. The local topography around a river can be developed using survey information of the river channel or from a Digital Elevation Model (DEM). For each 20-degree increment around a model segment, an array of elevation points and their distances from the center point are obtained from the DEM. The elevations and distances are then used to calculate the highest inclination angle relative to the center point. Inclination angles are generated for each of the 20-degree increments around a segment's center point. The inclination angles are converted to radians and specified in the dynamic shading input file. The first column represents the topographic inclination angle at 0° north with subsequent inclination angles obtained by moving clockwise.

    The shade algorithm can be used in both the northern and southern hemispheres. If there is no topographic shading in a specific direction due to the latitude or surrounding terrain, zero can be used as the inclination angle. The model uses all 18 topographic inclination angles. Based on the position of the sun, the algorithm will interpolate between the two nearest inclination angles to obtain the most appropriate inclination angle.

    Atmospheric Deposition Input File¶

    The atmospheric deposition input file (atm_deposition_wbX.csv) specifies wet and dry atmospheric deposition rates for each constituent for each waterbody. Atmospheric deposition is a process where either dry or wet deposition (rain or snow) of pollutants contribute to the mass loading of a pollutant. Dry deposition can include dust or particle transport associated with the pollutant. The processes of atmospheric deposition include Hg, P, N, and other state variables in CE-QUAL-W2.

    For the CE-QUAL-W2 model, the mass deposition rate is in units of kg km⁻² year⁻¹. This unit is often reported by researchers and is more practical than g m⁻² s⁻¹. Internally in the model, unit conversions are applied such that the internal source/sink term units are g s⁻¹ after multiplying by the area. For a variable with units of µg m⁻³ (ng L⁻¹), the atmospheric deposition rates are in units of mg km⁻² year⁻¹.

    The mass load is applied to each waterbody, rather than to each branch, since one would expect the areal deposition to be inclusive of branches and segments making up a waterbody.

    The input format is similar to all other time series input files, in CSV format. The $ character should be the first character in cell A1.

    2+ Constituent names Atmospheric mass deposition rate for each active constituent kg km⁻² year⁻¹

    Hypolimnetic Aeration Input File¶

    The hypolimnetic aeration input file (w2_aerate.npt) specifies parameters for the hypolimnetic aeration algorithm. The model reads this file if the AERATEC control is set to ON in the control file (w2_con.npt or w2_con.csv). This input file allows the user to:

    1. Add oxygen mass to specified model segments and layers
    2. Control the oxygen mass added by using oxygen probes located anywhere in the model domain
    3. Increase the mixing associated with the oxygen input

    This algorithm does not model the dynamics of a bubble diffuser. It allows the user to experiment with delivering oxygen at given rates to parts of the reservoir domain. This is useful for planning, since it allows the user to determine the amount of oxygen required to meet a water quality target.

    Error Trapping

    Error trapping for the USGS blending routine checks the following conditions:

    • At least 2 and no more than 10 outlets must be specified for NOUTS in each blending group on the SPLIT2 input card

    Volume-Weighted and Surface-Weighted Averages¶

    Volume-weighted averages are computed at specified segments. The output includes Julian day and the following parameters at each specified segment: PO₄, NH₄, NO₃, DO, TP, Chl-a, and Gamma (an index variable).

    Organic Matter Accumulation¶

    The organic matter accumulation output file contains comma-delimited entries for each segment and time of output. The values are grams of organic matter at the bottom of each layer, summed for each segment.

    Preprocessor¶

    The preprocessor produces several output files: a file that echoes all control file inputs along with additional information (pre.opt), a warning file that alerts the user to potential problems with inputs (pre.wrn), and an error file (pre.err) that identifies serious problems in the input data that may prevent the model from running or running correctly. Run the preprocessor routinely before a model simulation.

    In the Windows version, the user can supply a command-line working directory argument so that the preprocessor executable does not need to be copied into every model directory:

    preW2_ivf.exe "C:\scott\w2workshop\2009 workshop\waterqual\problem3"

    Warning Messages (pre.wrn)¶

    The preprocessor does an extensive check of inputs to determine if inputs "make sense." Because the model is flexible, certain inputs are not necessarily errors but should be flagged so the user can verify their intent. When kinetic rates differ from valid ranges or a specific value that should not normally be changed, a warning message is generated.

    All warning messages include a concise statement in English showing what the problem is. The Fortran variable name is also included along with its value.

    Example:

    Epiphyton excretion rate [EE=0.000] < 0.001 for epiphyton group 1
Oxygen to algal respiration stoichiometry [O2AR=1.400] /= 1.1 for waterbody 1
Phosphorus/organic matter stoichiometry [ORGP=0.011] /= 0.005 for waterbody 1
Water surface elevation is below bottom elevation at segment 1
Water surface elevation is below bottom elevation at segment 2

    Warning Messages

    The absence of warning messages does not guarantee that all inputs are correct. Not all possible input combinations can be checked. Do not assume that because there are no warnings generated there are no problems with inputs.

    Error Messages (pre.err)¶

    Input errors that will prevent the model from running correctly or running at all are extensively screened and, when found, are included in the preprocessor error output file. All error messages include a concise statement in English along with the Fortran variable name and its input value.

    Example:

    Starting time [TMSTRT=75.000] < ending time [TMEND=-320.000]
Timestep fraction [DLTF(1)=-0.850] <= 0.0
Internal gravity wave limitation control  [CELC= on] /= " ON" or "OFF" for waterbody 1
Heat exchange solution control [SLHTC= term] /= " TERM" or " ET" for waterbody 1
Vertical advection time weighting [THETA=-0.550] < 0.0 for waterbody 1
Selective withdrawal elevation [ESTR=137.700] < the bottom active cell elevation

    TECPLOT Output¶

    When the TECPLOT option is ON, the output consists of elevation (m), longitudinal distance (m), U (x-velocity, m s⁻¹), W (z-velocity, m s⁻¹), T (°C), RHO (kg m⁻³), Fish Habitat number, and concentrations for all active constituents for the entire grid at the time interval specified in CPL FREQ. Tecplot can read the file directly and the user can create contour animations of any variables including superimposed velocity vector plots.

    The Fish Habitat number is the fish criterion satisfied at each grid point (K,I). Define fish criteria in order of more restrictive to least restrictive:

    OptimalFishX,12.0,18.0,5.0
SuboptimalFishX,10.0,22.0,5.0
NonOptimalFishX(Lethal),0.0,35.0,4.0

    The first fish is given #1, second #2, and 3rd fish group #3. For each grid point, the habitat criteria value 1, 2, 3, or 100 (if outside the last range) is written to the Tecplot output file.

    To create a contour animation in Tecplot:

    1. Import data (cpl.opt) into Tecplot using the Tecplot Data Loader.
    2. Turn ON contours.
    3. Reset axes so that they are Independent (Tecplot default is dependent).
    4. Turn on Value Blanking since state variables outside the domain are set to -99.
    5. Reset the contour intervals since Tecplot automatically uses -99 as its minimum data value.
    6. Go to the animation and view the zones on screen or export to an AVI file.
    7. To add vectors, turn on vectors and choose U and W as the vector variables.

    Mass Balance Output File¶

    When mass balance [MBC] is turned ON and the contour plot is active, the model outputs a summary of N and P mass balances for each waterbody in the file massbal.csv. The file includes:

    • Julian day and waterbody number
    • Total phosphorus and total nitrogen in water column (kg), sediments (kg), and plants (kg)
    • Cumulative TP and TN in outflow, tributaries, distributed tributaries, withdrawals, precipitation, and inflow (kg)
    • Cumulative sediment release and flux to sediments (kg)
    • Sediment diagenesis flux terms (kg)

    Flow Balance Output File¶

    When volume balance [VBC] is ON and the contour plot is active, the model outputs a flow balance summary for each waterbody in flowbalance.csv. The file includes:

    • Julian day and waterbody number
    • Inflow volume (m³) from Qin files, precipitation, outlet structures, withdrawals, evaporation, distributed tributaries, tributaries, and ice formation/melting
    • Cumulative volumes and percent error

    SYSTDG Output File¶

    TDG (Total Dissolved Gas) concentrations computed with the SYSTDG equations are written into the withdrawal output files. Withdrawal outflow files contain information with release or withdrawal TDG concentrations in the time series output files. The model output consists of up to four separate files for the individual segment [IWDO] specified in the W2 control file. The files include an outflow, outflow temperature, constituent concentrations, and derived constituent concentrations. These files are for all the withdrawals specified at that segment lumped together if there are multiple withdrawals. All output files are in comma-delimited format. Also, whenever withdrawal output is ON, a series of individual files is also written in the output file for each structure at the withdrawal segment.

    An additional TDG target output file, TDGTarget_output.opt, is generated from the model if TDGTA is turned ON. This file contains information for outflow release or spillway TDG concentrations and outflows as a time series file.

    When the lake_river_contour.csv input file is present, the model produces output files for lake and river contour plots:

    • LakeContour_DO_SegXX.csv: Lake contour for dissolved oxygen at segment XX
    • Lake_Contour_T_SegXX.csv: Lake contour for temperature at segment XX
    • RiverContour_DO_BrYY.csv: River contour for dissolved oxygen for branch YY
    • RiverContour_T_BrYY.csv: River contour for temperature for branch YY

    Two output formats are available:

    1. Format 1: Columns of JDAY, elevation (or distance), and temperature/dissolved oxygen (DO) value
    2. Format 2: Elevations (or distances) in the first row; rows are time steps with temperature/DO values at each elevation (or distance)

    Water Level Output File¶

    A water level output file (wl.csv) is written when time series output is ON. The file contains the water surface elevation at every model segment as a function of time. The format is:

    JDAY,SEG    2,SEG    3,SEG    4,...,SEG   65,SEG
1.001,1484.700,1484.700,1484.700,...
1.150,1484.700,1484.700,...

    W2Anim Output File¶

    If the user uses Stewart Rounds' W2Anim post-processor (https://github.com/sarounds/w2anim/releases/latest), one of the files used for viewing the flow, temperature, and water quality of outlets is now automatically output. This file is used for viewing the outlet dynamics (flow, temperature, and water quality) for any outflow. The output file is written whenever there is a WDO (withdrawal output) specified.

    The file is internally named based on the prefix and suffix specified for the WDO output file. The file name is qwo_layers_XX_wdo.csv if the prefix was wdo and the suffix was csv, where XX is the segment number where the withdrawal occurs. The file contains:

    • Row 1: Header identifying the file as "Flow layers file for segment XX"
    • Row 2: Column headers including "Output is total outflow, WS elev, El(Kbm)" and "layer outflows starting w/ layer 2"
    • Row 3: Column labels for JDAY, Q(m3/s), El(Kbm), and LayerFlow(m3/s)
    • Subsequent rows: Time series of Julian day, total outflow, water surface elevation, bottom elevation, and flow in each layer starting with layer 2

    The column D starts with the flow in layer 2, column E is the flow in layer 3, and so on.

    Run-time Warnings¶

    The model generates run-time warning messages to the file w2.wrn. These include:

    • Water surface above grid: Water surface elevation is above the top of layer 2 at a segment.
    • Computational warning: Velocities approaching supercritical values with a negative surface layer thickness.
    • Unstable water surface elevation: The model decreases the timestep by 90% and recomputes.
    • Low water: A segment has only one active layer remaining.
    • Volume error: Volume error exceeds 1000 m³.
    • Surface layer changes: Layer addition or subtraction information.

    Instability Recovery

    When the model detects an unstable water surface elevation, it attempts recovery by decreasing the timestep. If the current timestep is less than or equal to DLTMIN, the model stops and writes an error message to w2.err. To recover, reduce DLTMAX and/or DLTF near the time of instability.

    Run-time Errors¶

    When the model becomes unstable and stops, it generates two error files:

    W2.err¶

    This file contains error messages with diagnostic information including segment number, water surface elevation, bottom elevation, and elevation differences for all segments in the offending branch.

    Common errors:

    • Unstable water surface elevation on day 'x' negative surface layer thickness using minimum timestep at iteration 'y'
    • Fatal error: Insufficient segments in branch 'x' Julian day = 'y' water surface layer = 'z'

    W2ErrorDump.csv¶

    This file provides comprehensive diagnostic data at the time of model crash, including:
